## 영상 기반 업무 흐름 *(실제 화면에서 확인 필요)*

1. 연구관리 탭의 `내 과제 관리 → 지출신청(연구자용)`으로 이동한다.
2. 검색 조건에 기타소득 대상 과제번호를 입력하고 조회한다.
3. 지출구분에서 `인건비`를 선택한다.
4. `기타소득 인건비 지급신청` 팝업에서 지급 내역을 입력한다. 주황색 셀은 필수 입력값으로 안내된다.
5. 지급 귀속연월을 입력하면 해당 월의 기타소득 지급 대상자 목록이 자동 생성되는 것으로 영상에서 안내한다.
6. 신청 제목을 입력한다.
7. 사용자가 직접 저장 및 신청을 수행한 뒤, 초기 목록에서 생성한 인건비 내역을 찾아 체크하고 청구한다.
8. 청구 뒤 결의는 연구행정실 및 기관 내부 절차이므로 연구자 자동화 범위에 포함하지 않는다.

## 1단계 실제 화면 기록 — 진입 및 지급신청 작성

기록 방식: 입력값과 화면 문구는 수집하지 않고, 실제 조작에서 확인된 컴포넌트 ID와 순서만 기록했다.

1. `지출신청(연구자용)` 화면의 검색 입력칸에서 대상 과제를 조회했다.
2. 지출구분에서 인건비를 선택해 신규 지급신청 화면을 열었다. 이 전환 과정의 클릭 대상은 Nexacro `div`로만 기록되어 실제 버튼 ID는 다음 화면 조사에서 보완한다.
3. 지급신청 화면에서 귀속연월 달력과 입력칸을 조작했다.
4. 신청 제목을 입력했다.
5. 실제 업무에서는 사용자가 `저장 및 신청`을 직접 누른다. 이번 기록 환경에서는 신청이 처리되지 않아, 해당 버튼의 ID·후속 목록 상태는 2단계에서 확인한다.

### 실제 확인된 컴포넌트

| 화면 라벨 | 컴포넌트·데이터셋 | 입력 형식 | 자동화 여부 | 비고 |
|---|---|---|---|---|
| 과제 조회 입력 | `FrameSet_0120180000_form_div_workForm_div_search_edt_searchText_input` | 문자열 | 사용자 선택 | 실제 과제번호는 기록하지 않음 |
| 귀속연월 달력 버튼 | `FrameSet_0120180000_new_form_cal_payYymm_dropbuttonAlignImageElement` | 클릭 | 조건부 자동 | 화면 반영과 지급대상 생성 여부 확인 필요 |
| 귀속연월 입력 | `FrameSet_0120180000_new_form_cal_payYymm_calendaredit_input` | YYYY-MM | 조건부 자동 | 실제 형식·검증 규칙 확인 필요 |
| 신청 제목 | `FrameSet_0120180000_new_form_edt_aplyTtl_input` | 문자열 | 자동 | 실제 필수 여부·길이 확인 필요 |

### 1단계 미확인 항목

- 인건비 선택 버튼·지급신청 호출 버튼의 실제 ID
- 주황색 필수 셀 전체와 지급 대상자 자동 생성 조건
- `저장 및 신청` 버튼의 실제 ID, 성공 뒤 목록 행의 식별 방식
- 신청 실패 원인과 오류 메시지 (실제값·화면 문구는 기록하지 않음)

## 2단계 실제 화면 기록 — 목록의 생성 내역 선택

1. 지급신청 뒤 초기 목록 화면으로 돌아온다. 이 단계에서는 직전에 저장·신청한 인건비 내역을 대상으로 한다.
2. 결과 목록 영역에서 해당 내역을 선택했다. 기록된 컨테이너 ID는 `FrameSet_0120180000_form_div_workForm_div_right_Div00ScrollableContainerElement`이다.
3. 이어진 두 클릭은 Nexacro `div`로 기록되어 대상 요소의 실제 ID를 확인하지 못했다. 교육영상의 흐름상 행 체크 또는 청구 준비 동작일 수 있으나, 실제 라벨·버튼 ID는 다음 조사에서 확인한다.
4. `청구`는 사용자 최종 처리이므로 자동화하지 않는다.

### 2단계 자동화 경계

| 작업 | 처리 주체 | 확인 상태 |
|---|---|---|
| 직전에 저장·신청한 인건비 내역 식별 | 사용자 | 실제 선택 과정 확인 |
| 해당 목록 행 또는 체크박스 선택 | 사용자 | 대상 요소 ID 미확인 |
| 청구 버튼 실행 | 사용자 | 자동화 금지 |

## 최종 제출용 통합 절차

### 범위

SRnD에서 기타소득 인건비 지급신청을 작성하고, 신청 뒤 초기 목록에서 해당 내역을 확인하는 과정이다. 자동화 범위는 화면 입력과 화면 상태 확인까지이며, `저장 및 신청`과 `청구`를 포함한 최종 처리는 사용자가 직접 수행한다.

### 1단계 — 지급신청 작성

1. 사용자가 SRnD 로그인과 위임계정 전환을 완료한다.
2. `연구관리 → 내 과제 관리 → 지출신청(연구자용)`으로 이동한다. 메뉴의 실제 화면 ID는 확인 필요다.
3. 기타소득 대상 과제를 조회한다. 복수 결과 또는 판단이 필요한 과제는 사용자가 직접 선택한다.
4. 지출구분에서 `인건비`를 선택해 기타소득 인건비 지급신청 화면을 연다. 선택 버튼의 실제 ID는 확인 필요다.
5. 귀속연월을 입력한다. 확인된 입력 요소는 `FrameSet_0120180000_new_form_cal_payYymm_calendaredit_input`이다.
6. 귀속연월 변경 뒤 지급 대상자 목록이 자동 생성되는지와 필수값을 확인한다. 대상자·금액·지급 내역은 사용자가 검토한다.
7. 신청 제목을 입력한다. 확인된 입력 요소는 `FrameSet_0120180000_new_form_edt_aplyTtl_input`이다.
8. 사용자가 화면을 검토한 뒤 `저장 및 신청`을 직접 수행한다. 이 버튼은 자동화하지 않는다.

### 2단계 — 신청 내역 확인 및 청구 직전

1. 신청 뒤 초기 목록 화면으로 돌아온다.
2. 직전에 저장·신청한 인건비 내역을 결과 목록에서 사용자가 식별한다. 확인된 목록 컨테이너는 `FrameSet_0120180000_form_div_workForm_div_right_Div00ScrollableContainerElement`이다.
3. 해당 행 또는 체크박스를 사용자가 선택한다. 실제 행·체크박스 ID는 확인 필요다.
4. 사용자가 선택 결과를 검토한 뒤 `청구`를 직접 수행한다. 청구는 자동화하지 않는다.
5. 청구 이후 결의는 연구행정실 및 기관 내부 절차이므로 이 기능의 자동화 범위에 포함하지 않는다.

- [x] 결과 목록 컨테이너의 실제 ID를 기록함

- [ ] `저장 및 신청` 성공 뒤 생성 행의 실제 식별 방식 확인

## 사전 조건

- 실제 과제·연구원·금액·일자·신청 내용은 조사 과정에서만 사용하며 기록 파일에 남기지 않는다.

## 실제 변경신청 흐름

1. 좌측 메뉴에서 `연구관리 > 내과제관리 > 참여연구원 > 참여연구원등록/변경(연구자용)`으로 이동한다. 처음에는 `내과제관리`와 `참여연구원`을 펼친다.
2. 상단의 `변경신청` 탭을 선택한다. 화면에는 `신청목록`, `등록신청`, `변경신청` 탭이 있다.
3. 필요한 검색 조건을 지정하고 조회한다. 화면에서 확인된 조건은 연구기간, 처리상태, 사업구분, 검색조건, 신청구분, 진행상태다. 이번 조사에서는 신청구분 `연구원변경`을 사용했다.
4. 과제번호 돋보기로 `과제조회(팝업)`을 열어 검색조건을 입력하고 조회한다.
5. 조회 결과에서 과제를 선택하고 `확인`으로 돌아온다. 자동화는 입력 조건과 일치하는 결과가 정확히 한 건일 때만 선택할 수 있으며, 복수 결과는 사용자가 선택한다.
6. 과제정보가 채워진 변경신청 화면에서 `참여연구원` 목록의 대상 행을 선택한다.
7. 대상 행의 행 선택 체크박스를 선택한 뒤 `변경구분`을 `변경`으로 지정한다. 대상 행의 선택은 자동화하지 않는다.
8. 대상 행의 상세 영역에서 필요한 값을 수정한다. 이번 조사에서 참여기간, 연구원그룹, 인건비예산, 지급구분, 소득구분, 월 기준금액, 계상률/월 지급액, 월 기관부담금, 월 퇴직적립금, 월 식대비과세, 산학협력단 신고, 장학생, 학생인건비 컨트롤을 확인했다.
9. 이번 실제 변경에서는 계상률/월 지급액의 비율 입력을 변경했고, 해당 값과 연동되는 지급액 영역이 표시됐다. 자동화 전에 재계산 규칙과 허용 범위는 추가로 검증해야 한다.
10. `신청내용`에 변경 사유를 입력한다.
11. 저장 직전 상태에서 사용자가 전체 변경 내용을 검토한다. 화면의 `저장`을 누르면 확인 팝업이 열리지만, 자동화는 저장 및 팝업의 `확인`을 절대 누르지 않는다.

## 화면에서 확인한 분기와 주의점

| 조건 | 처리 |
|---|---|
| 과제 조회 결과가 0건 | 자동화를 멈추고 조회 조건을 사용자에게 확인한다. |
| 과제 조회 결과가 복수 건 | 자동 선택하지 않고 사용자가 행을 선택한다. |
| 변경 대상 연구원이 복수 명 | 자동 선택하지 않고 사용자가 대상 행을 선택한다. |

| 저장 확인 팝업 표시 | 사용자 최종 처리 단계다. 자동화는 `저장`, 팝업 `확인`, `신청`, `삭제`를 누르지 않는다. |

## 구현 범위

- `extract.js`, `fill.js`, `sample.json`은 **변경신청만** 지원한다.
- `fill.js`는 사용자가 과제와 대상 참여연구원 행을 선택한 뒤, 확인된 `신청내용` 및 선택적인 계상률/월 지급액 비율만 입력한다.
- 등록신청, 대상 행 자동 선택, 변경구분 자동 판단, 지급조건 세부 필드 자동 입력은 현재 조사 범위 밖이며 구현하지 않는다.

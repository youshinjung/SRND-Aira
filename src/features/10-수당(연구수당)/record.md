## 사전 조건

- 필요한 권한: 연구자 계정, 해당 과제 참여연구원 권한
- 사용자가 직접 완료할 로그인·계정전환: 로그인, 위임계정 전환
- **위임계정 전환 UI 위치** (실제 화면 확인): 화면 상단 헤더 바, 로그인한 직원 이름 옆에 위임 대상(연구책임자) 이름이 드롭다운으로 표시됨 (예: "○○○(학생) [로그인한 직원명] 님 [드롭다운: 위임대상 이름] 님"). 드롭다운을 클릭해 위임 대상을 선택하면 화면이 그 연구책임자 권한으로 전환됨.
  - **주의**: 페이지를 새로고침(F5)하면 위임계정 전환이 풀리고 로그인한 직원 본인 계정으로 돌아감. 이때 상단 탭 구성도 달라짐 — 본인 계정: `연구관리 / 운영지원 / 지식재산권 / 업무요청관리 / 공통관리`, 위임계정: `연구관리 / 연구성과 / 연구활동지원 / 예산회계 / 구매자산 / 지식재산권 / 공통관리`. `지출신청(연구자용)`은 위임계정 상태에서만 보임. 새로고침 후에는 위임계정을 다시 선택해야 함.

## 클릭 순서

### 메인 화면(`RMSRFME590Z`) 필드 구조 (실제 확인)

좌측 "수행과제정보" 조회 영역:
- 연구기간 (시작~종료 날짜, 프리셋 1년/3년 버튼)
- 과제상태 라디오: 전체 / 진행 / 종료
- 검색조건 드롭다운(예: "과제번호") + 텍스트박스
- 연구책임자 (사번 + 돋보기 + 이름, 위임계정 기준으로 자동 표시되는 것으로 보임)
- 상단 툴바 `조회` 버튼 클릭 → 좌측 "수행과제정보" 표(순번/과제번호/과제명/연구책임자/시작일)에 결과 표시

우측 "지출신청" 영역:
- 안내문구: "지출구분 선택 시, 신규 작성 가능합니다"
- **지출구분 라디오 그룹** (17개 기능 중 다수와 공유 — 위 "신규 발견" 절 참고): 일반지급/회의비/여비/전문가활용비/학술행사등록/식대/구매지출/인건비/**수당**/도서구매/지출반납/과목경정/이관(학생인건비,연구시설)/기관부담금·퇴직적립금
- 그 아래 "검색조건" 박스 (기존/제출된 신청 내역을 조회하는 영역으로 보임): 버튼 `저장`/`조회`/`청구`/`청구취소`/`계좌이체확인서`/`연구비청구및지급`, 필터(신청기간, 검색조건 드롭다운 2단, 청구여부 라디오, 결의상태 라디오)
- "검색결과" 표: 순번/체크박스/지출구분/신청구분/지급신청금액/세목/비용/제목/청구번호... (우측으로 더 스크롤 필요, 다 못 봄)

→ 영상에서 말한 "검색 결과로 돌아와 방금 입력한 연구수당 지급란을 찾아 체크 후 청구 버튼"이 바로 이 "검색결과" 표 + `청구` 버튼으로 확인됨.

### 클릭 순서 (실제 화면 기준으로 재정리, 이번 회차 진행 중)

1. `내과제관리` > `지출신청(연구자용)` 메뉴 진입 (위임계정 상태 확인 — 새로고침 시 풀림, 위 "사전 조건" 참고)
2. 좌측에서 연구기간/과제상태/검색조건으로 대상 과제 좁히고 `조회` 클릭 → 수행과제정보 표에 과제 나타남
3. 우측 지출구분 라디오에서 `수당` 선택 → "신규 작성 가능" 안내대로 `수당 지급신청` 팝업 호출 (다음 단계 진행 중, 이후 내용은 아래 기존 기록대로)
4. 팝업 내 청구정보 입력 (주황색 셀 = 필수값 — 실제 화면에서도 주황 테두리로 확인됨: 세목/비용, 실사용자, 제목, 연구수당평가기간)
5. 팝업 상단 버튼: `저장` / `삭제` / `신청` / `신청취소` / `사용내역서 출력` / `사용내역서 자동첨부` — **`저장`·`삭제`·`신청`·`신청취소`는 모두 상태를 확정/변경하는 동작이라 자동화 금지 대상으로 취급**(SECURITY.md의 "삭제·취소 확정" 금지 조항에 `신청취소`도 해당한다고 판단)
6. 팝업 닫고 메인 화면의 "검색결과" 표로 복귀 → 방금 입력한 연구수당 지급 행 체크 → `청구` 버튼 클릭 ← **최종 처리, 자동화 금지** (실제 버튼 존재는 확인, 클릭 전까지의 정확한 흐름은 다음 회차에 재확인)
7. (연구자 작업 범위 밖) 이후 결의는 관리기관 담당자가 기한·내부결재로 진행

이전 회차에서는 팝업이 이미 값이 채워진 상태로 시작해서 표를 중간 지점부터 스크롤했고, 그 결과 왼쪽 컬럼(성명·기여도·지급액)을 놓치고 "1명 기준"이라고 잘못 결론냈습니다. 이번에 빈 팝업 상태(행 없음)에서 다시 확인하니 `지출대상자 지급내역` 표의 실제 컬럼은 다음과 같습니다 (왼쪽부터):

`순번, 체크박스, 상태, 역할, 성명, 소득구분, 상세소득구분, 장학생여부, 기여도, 지급총액, 지급액` + (오른쪽으로 계속: 이전에 확인한 `비과세, 소득세, 주민세, 개인 4대보험, 기관 4대보험/산재보험, 퇴직적립금`)

→ 성명·기여도·지급액 컬럼이 실제로 존재합니다. 즉 영상 설명(참여연구원별로 기여도를 입력하는 표)이 맞았던 것으로 보이고, `과제참여연구원불러오기` + `행추가` 버튼으로 이 표에 참여연구원을 여러 행 추가해서 각자 기여도·지급액을 입력하는 구조일 가능성이 높습니다. `기여도신청불러오기`는 이 값들을 한 번에 채우는 보조 기능(19-2 기여도평가서를 미리 등록해두면 자동으로 채워주는 기능)일 수 있습니다.

다음 조사 때 확인할 것 (아직 실행 안 해봄): `과제참여연구원불러오기` 클릭해서 실제로 몇 명이 뜨는지, 여러 행을 추가할 수 있는지, `실사용자`/`신청금액` 필드가 이 표와 어떻게 연동되는지(합계? 대표 1인?).

### 19-2. 연구수당 기여도 평가서 (붙임 5-1)

**1. 일반사항**: 과제번호, 연구책임자, 연구기간, 평가기간, 연구수당 총 예산, 금번 지급 예산

**2. 평가 내용 표**: 평가항목(연구과제 수행/연구결과물/연구결과 발표/기타 — 과제별로 수정 가능) × 참여연구원별 평가점수. 평가항목별 배점 합계는 100점 고정. 참여연구원별 "금번 지급액에 대한 기여도(%)" = 참여연구원 평가점수 총합 × (금번 지급 예산 / 연구수당 총예산)

→ 이 기여도(%)가 19-1 지급내역 표의 "기여도(B)"로 그대로 연결됨. 즉 **기여도는 기여도 평가서에서 산출되어 지급신청서로 옮겨지는 값**이라 자동화 시 두 문서/화면 간 정합성 검증이 필요. (위 "신규 발견" 절에서 추정한 `기여도신청` 메뉴가 바로 이 문서의 디지털 버전일 가능성이 높음)

### 연구수당-부당집행 기준 안내 및 계산식.xlsx (참고용, 검증 로직 힌트)

SRnD 화면 항목은 아니지만 연구자가 스스로 부당집행 여부를 점검하는 계산식 시트. 핵심 로직:

- 연구수당 집행비율 = 연구수당 집행액 / 연구수당 계상액 × 100
- (이월금 포함) 직접비 집행비율 = (직접비 집행액 + 전년도 이월금 중 직접비 집행액) / 직접비 계상액 × 100
- **위반 조건**: 연구수당 집행비율 − 직접비 집행비율 > 20%p 이면 초과분만큼 반납액 발생 (`연구수당 계상액 × (연구수당집행비율% − 직접비집행비율% − 20%)`)

→ `extract.js`에서 연구수당 신청 전 이 비율을 계산해 사용자에게 경고(반납 위험)해주는 것이 유용할 수 있음. 단, 화면 기록이 아직 부족해 지금 코드화하지 않고 record.md에만 남겨둠.

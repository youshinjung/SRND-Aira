# 02 회의비 모듈

## 적용 흐름

1. 사용자가 SRnD에서 `내과제관리 → 지출신청(연구자용)`으로 이동한다.
2. 사용자가 과제를 선택하고 지출구분에서 `회의비`를 선택해 회의비 팝업을 연다.
3. 사용자가 기존 **SRND 양식 자동입력** 앱에서 `회의비지급신청`과 증빙 PDF를 선택한다.
4. 앱이 이 모듈의 `extract()`로 PDF 텍스트를 해석하고 `fill()`에 현재 열린 팝업과 입력 데이터를 전달한다.
5. 모듈은 일자, 시간, 장소, 목적, 회의내용, PDF 첨부까지만 처리하고 멈춘다.

## 자동화 경계

| 작업 | 처리 주체 |
|---|---|
| 로그인·위임계정 전환 | 사용자 |
| 메뉴 이동·과제 선택·지출구분 회의비 선택 | 사용자 |
| 열린 회의비 팝업의 핵심 필수칸 입력 | 모듈 |
| 첨부 창이 열린 상태에서 PDF 업로드 | 모듈 |
| 참석자·카드·과제 등 복수 조회 결과 선택 | 사용자 |
| 저장·신청·청구·제출·승인·삭제 | 사용자 |

## 확인된 입력 대상

| 화면 필드 | 선택자 패턴 | PDF 출처 |
|---|---|---|
| 일자 | `cal_useDt_calendaredit_input` | 회의일시 |
| 시작 시간 | `cal_useFrTm_calendaredit_input` | 회의시간 |
| 종료 시간 | `cal_useToTm_calendaredit_input` | 회의시간 |
| 장소 | `edt_usePlNm_input` | 회의장소 |
| 회의목적 | `edt_usePurp_input` | 회의목적 |
| 회의내용 | `txt_aplyCtnt_textarea` | 회의결과 |

## 안전 규칙

- 열린 회의비 팝업이 발견되지 않으면 입력하지 않고 오류로 중단한다.
- PDF의 필수 정보가 없거나 화면 값 반영을 확인할 수 없으면 중단한다.
- 실제 증빙 PDF·추출 결과·로그인 정보·개인정보를 저장소에 저장하지 않는다.
- 저장, 신청, 변경신청, 발급신청, 제출, 청구, 승인, 삭제 또는 동등한 최종 동작을 하지 않는다.

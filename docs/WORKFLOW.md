# 기능 구현 표준 절차

## 1. 기능 시작

1. `docs/FEATURES.md`에서 번호와 제목을 확인한다.
2. 해당 기능 폴더의 `STATUS.md`를 `조사중`으로 변경한다.
3. `templates/feature/`의 네 파일을 기능 폴더로 복사한다.
4. 교육영상과 사용자가 제공한 대본·설명을 검토한다.

## 2. 실제 화면 기록

1. 터미널에서 기록 도구를 실행해 외부 Google Chrome을 연다.
2. 사용자가 로그인과 위임계정 전환을 직접 완료한다.
3. 사용자가 기능 화면의 실제 클릭 순서와 모든 분기를 수행한다.
4. 다음 지점에서 화면 구조를 기록한다.
   - 메뉴와 탭 진입
   - 신규 또는 행추가 직후
   - 돋보기·콤보·달력 팝업
   - 조회 결과와 행 선택
   - 조건에 따라 필드가 생기거나 사라지는 시점
   - 최종 저장 직전 준비 상태
5. 최종 버튼은 누르지 않는다.

실제 입력값은 화면 확인에만 사용한다. 값 자체를 JSON, Markdown, 로그 또는 스냅샷 설명에 남기지 않는다. `record.md`에는 컴포넌트 구조와 조작 순서만 개인정보 제거 상태로 기록한다.

## 3. 구현 경계 결정

각 조작을 다음 중 하나로 분류해 `record.md`에 기록한다.

- 자동: 결과가 한 개로 확정되고 안전하게 재현 가능한 입력·선택
- 조건부 자동: 입력 데이터로 유일한 결과를 식별할 때만 수행
- 사용자 선택: 동명이인, 복수 카드, 복수 과제 등 업무 판단이 필요한 선택
- 사용자 최종 처리: 저장·신청·청구·승인·삭제 등 되돌리기 어렵거나 권한이 필요한 처리

## 4. 테스트 우선

1. `.work/` 아래에 테스트 CMD와 임시 테스트 도구를 만든다.
2. 테스트 CMD는 필요한 경우 실제 과제번호나 조회명을 실행 중 입력받을 수 있다.
3. 입력값은 메모리에서만 사용하고 파일에 저장하지 않는다.
4. 사용자에게 CMD 실행 명령부터 제공한다.
5. 터미널 로그와 사용자 화면 확인 결과를 바탕으로 반복 수정한다.
6. 여러 분기를 연속 시험할 때는 다음 분기 전에 이전 행·체크박스·팝업 선택을 해제한다.

## 5. 최종 파일

기능 폴더에는 다음 네 파일만 구현 산출물로 둔다.

- `extract.js`: 입력 문서에서 기능 스키마를 추출하고 사용자 검토용 결과를 반환
- `fill.js`: 검토된 입력을 SRnD 화면에 채우고 최종 처리 직전에 정지
- `record.md`: 메뉴 경로, 화면 ID, 필드, 분기, 수동 단계와 금지 동작 기록
- `sample.json`: 완전히 가상의 값으로 작성한 기능 스키마 예시

`real-data.json` 또는 실제 입력을 재현하는 파일은 만들지 않는다.

## 6. 완료 검사

- `extract.js`와 `fill.js` 문법 검사를 통과한다.
- `sample.json`이 정상적으로 파싱된다.
- 샘플의 사람·과제·계좌·카드·연락처 값이 전부 가상이다.
- 모든 기록된 분기가 코드 또는 명시적인 사용자 단계로 처리된다.
- 금지된 최종 버튼을 클릭하는 코드가 없다.
- 로그인 정보, 실제 입력, 스냅샷 덤프와 테스트 CMD가 Git 변경 목록에 없다.
- 사용자가 실제 화면 테스트 완료를 확인했다.

검사를 통과한 뒤에만 `STATUS.md`와 `docs/FEATURES.md`의 상태를 `구현완료`로 바꾼다.
